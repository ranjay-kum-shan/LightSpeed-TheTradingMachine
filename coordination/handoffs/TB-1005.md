## Completion Summary

`src/trading_bot/audit/` now holds the structured event schema and the single
redaction boundary that every log line must pass through.

`AuditEvent` carries every field of the
[structured event contract](../../docs/08-operations-and-observability.md),
normalizes both timestamps through the TB-1004 `ensure_utc` primitive, refuses a
record time earlier than the occurrence time, and requires a stable dotted
lowercase `event_type`. Scope identity is enforced by mode: a `BACKTEST` event
requires `run_id`, and `PAPER` or `RECOVERY` events require `session_id`. AUD-001
is enforced structurally: an event whose type begins with `decision.` cannot be
constructed without `strategy_id`, `git_revision`, `config_hash`, `data_hash`,
`reason_code`, and a non-empty payload.

`Redactor` is the boundary. It masks registered canary literals anywhere,
secret-named keys at any nesting depth, URL userinfo, query and header pairs
whose name is credential-like, and authorization scheme values, including inside
multiline strings and nested arrays. It refuses anything it cannot classify:
arbitrary objects, exceptions, `datetime`, sets, binary values, and non-string
mapping keys all raise `RedactionFailure` rather than being stringified.
`serialize_event` renders one canonical JSON line and then rescans the rendered
line, raising if any known secret survived.

**Open boundary question for the coordinator.** `audit` is a new package that the
[architecture module table](../../docs/02-architecture.md) does not list; that
table assigns events to `domain`. The master tracker assigns this task the
`src/trading_bot/audit/**` write scope, and the architecture document states the
table is a planned contract rather than one class per box. The package was
created with an inward-only dependency direction. The coordinator should either
add the row to the architecture document or record acceptance of the deviation.

**Named deviation.** `OperatingMode` is imported from `trading_bot.config`
rather than redefined, so `audit` depends on a module that itself pulls in
pydantic and YAML. Duplicating a safety-critical mode enum would create two
sources of truth, which is worse. Moving `OperatingMode` into `domain` is a
cross-module change outside this write scope.

Residual safety or security risk: the guard is name-based and literal-based. It
cannot detect an unregistered secret carried in a value under an innocuous key,
so a caller that does not register its canaries with the `Redactor` gets pattern
coverage only. The pattern coverage is real but bounded: it masks credential-like
`key=value` and `key: value` pairs, authorization schemes, and URL userinfo, and
nothing else. All test canaries are synthetic strings beginning with `canary-`;
no real credential format is embedded anywhere. No sink, file, or network path is
introduced, so nothing yet writes an event to disk.
