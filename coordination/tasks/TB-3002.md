## Objective

Provide the typed canonical market-data values - instrument identity, daily bar,
corporate action, and dataset manifest - so ingestion, backtesting, and lineage
work share one schema instead of untyped provider payloads, and so a value whose
meaning would be undefined cannot be constructed at all.

## Scope

### In Scope

- `Instrument` identity value with internal ID, symbol, exchange, and currency.
- `DailyBar` canonical row with raw series, adjusted series, session identity,
  availability time, and provider traceability.
- `CorporateAction` canonical row with `CorporateActionType` and type-specific
  completeness rules for splits, cash dividends, and symbol changes.
- `DatasetManifest` with `DatasetType`, `ValidationResult`, lineage, hashes, and
  a canonical sorted request parameter list that refuses secret-like keys.
- `CANONICAL_SCHEMA_VERSION` for the schema family introduced here.
- Invalid-value tests for every rejection branch and for UTC normalization.

### Out of Scope

- `DV-001` through `DV-012` dataset validation, which TB-3005 owns.
- Provider clients, retrieval, Parquet serialization, content-hash computation,
  and snapshot publication, which TB-3006 and the ingestion tasks own.
- Universe membership schemas, which stay with the later cross-sectional
  research work rather than the Stage 1 single-instrument slice.
- The `available_at_utc` derivation policy, which TB-3004 owns.
- Live trading, real credentials, and owner-dependent values unless an approved
  higher-level decision explicitly changes the project boundary.

## Hypothesis and First Check

**Falsifiable local hypothesis:** a canonical `DailyBar` that is normalized from
an aware non-UTC timestamp keeps the same instant, and a bar whose
`available_at_utc` precedes its own `bar_close_utc` is refused, so no canonical
row can encode lookahead availability.
**Controlling code path:** `DailyBar.__post_init__` in
`src/trading_bot/data/models.py`, using `trading_bot.domain.time.ensure_utc`.
**Cheapest discriminating check:**
`uv run pytest -q tests/test_data_models.py -k "availability or utc"`.
**Expected failing or passing observation:** before the rule exists the lookahead
case constructs successfully and the test fails; after the rule exists the
constructor raises `ValueError` and the normalization case reports the identical
instant expressed in UTC.

## Decisions and Assumptions

| Item | Type | Evidence | Resolution or escalation |
| --- | --- | --- | --- |
| Canonical rows enforce representational rules only, not `DV-*` rules | Decision | Dataset lifecycle places `NORMALIZED` before `VALIDATING`, and `DV-004`, `DV-005`, `DV-001`, and `DV-002` must each report offending canonical rows | Prices, volumes, OHLC ordering, and duplicates stay representable so TB-3005 can quarantine them with stable codes |
| Non-finite numbers are refused in both `float` and `Decimal` form | Decision | The specification requires analytical numeric fields to reject NaN and infinity; a `Decimal` NaN also raises `InvalidOperation` when compared, which would escape a `ValueError` quarantine handler | `_require_finite` and `_require_finite_decimal` both raise `ValueError`, and the decimal check runs before any comparison |
| Lookahead is the one safety rule the schema enforces | Decision | Review cycle one showed the original comparison-semantics discriminator did not cover this case. No `DV-*` rule covers availability ordering, so nothing downstream would catch lookahead, and a lookahead row can never be reviewed into acceptance | Stated in the module docstring and the handoff; TB-3004 still owns how much later availability should be |
| Coverage bounds and lineage-graph integrity are not schema rules | Decision | Cycle one asked for an `effective_end` versus `retrieved_at_utc` guard (m3); cycle two proved it unsound without exchange context (N10) and untested (N4), and that self-parentage was only a length-one cycle check (N12) | Both rules removed; `DV-002` and `DV-010` cover coverage bounds, `DV-011` and `DV-012` cover lineage. Pinned by `test_manifest_leaves_lineage_rule_violations_representable` |
| Symbol-change comparison is exact, not case-insensitive | Decision | Cycle one flagged case sensitivity as a no-op loophole (m6); cycle two showed the casefold fix makes a genuine case-only provider rename unrepresentable (N11) and that provider symbols are deliberately not case-normalized | Reverted to exact comparison with the reason stated inline and a test for the rename |
| Manifest request parameters refuse secret-like keys | Decision | Specification requires a canonical sorted request excluding secrets | Normalized allowlist, exact-name, and fragment matching after findings M4 and N1; key names only, so TB-1005 still owns the general redaction boundary |
| Enum literals are uppercase, not the lowercase of the specification tables | Limitation | Matches `SessionType`, `OrderStatus`, and `ReasonCode`, but these values feed a future content hash | Needs a decision record before the first published dataset |
| Universe membership schema omitted | Assumption | Task title and Stage 1 fixed-allowlist policy cover instrument, bar, action, and manifest only | Raise a new task before broad cross-sectional research needs point-in-time membership |
| The master tracker was edited under the coordinator role | Limitation | Review finding M3; the protocol forbids an implementer from editing it | Disclosed in Ownership and Claim, the handoff, and the tracker change log; a separate coordinator should be appointed |
