## Objective

Provide one structured audit event value and one redaction boundary, so every
later component emits schema-valid append-only evidence and no secret, canary, or
arbitrary provider object can reach a log line.

## Contracts and Requirements

| Contract | Relevant section or invariant | Required behavior |
| --- | --- | --- |
| [Requirements](../../docs/01-requirements.md) AUD-001 | A decision log carries UTC time, run or session ID, strategy ID, code revision, configuration hash, data hash, inputs, decision, and reason code | A decision event missing any of these cannot be constructed |
| [Requirements](../../docs/01-requirements.md) NFR-SEC-004 | Allowlisted fields with mandatory redaction tests | Payload accepts only allowlisted value kinds; canary tests prove no secret escapes |
| [Operations Runbook](../../docs/08-operations-and-observability.md) Structured Event Contract | JSON Lines, one complete event per line, versioned schema, named fields, append-only | Field set and serialization match the table |
| [Security Specification](../../docs/07-security-and-secrets.md) Logging and Redaction | Never serialize SDK objects, sessions, environment mappings, exception output, or configuration objects; redaction covers nested mappings, arrays, URLs, headers, and multiline strings; redaction failure is a high-severity halt condition | Non-allowlisted values raise; every listed carrier is covered; a surviving secret raises |
| [Architecture](../../docs/02-architecture.md) Module Boundaries | Dependency direction points inward | `audit` imports the standard library, `domain`, and the single `OperatingMode` enum only |

Conflicting or missing contract: `audit` is not listed in the

## Scope

### In Scope

- `AuditEvent` with every field of the structured event contract, UTC
  normalization, and stable dotted event types.
- `Severity` and `AUDIT_SCHEMA_VERSION`.
- AUD-001 completeness enforcement for decision events.
- `Redactor` covering secret-named keys at any depth, known canary literals, URL
  userinfo, query and header pairs, and authorization schemes.
- A payload allowlist that refuses arbitrary objects, exceptions, and mappings
  that are not plain string-keyed structures.
- `serialize_event` producing one canonical JSON line with a final canary scan
  that raises on any surviving secret.

### Out of Scope

- Log sinks, file rotation, retention, and the append-only store, which belong to
  the operations and storage tasks.
- Alert routing and the daily report schema, which TB-6002 owns.
- Account fingerprint derivation and the approved account registry, which
  TB-5003 owns; this task only carries and redaction-checks the value.
- Migrating `src/trading_bot/data/models.py` onto this boundary, which is outside
  the approved write scope.
- Live trading, real credentials, and owner-dependent values unless an approved
  higher-level decision explicitly changes the project boundary.

**Approved write scope:** `src/trading_bot/audit/**`, `tests/test_audit.py`, and
this record plus its handoff. `MASTER-TASK-TRACKER.md` is also changed as a
coordinator action; see Ownership and Claim.

## Hypothesis and First Check

**Falsifiable local hypothesis:** a canary secret placed in a nested payload
mapping, inside a URL query value, inside an `Authorization` header line, and
inside a multiline string is absent from the serialized event line, and a payload
carrying a non-allowlisted object raises rather than being stringified.
**Controlling code path:** `Redactor.redact` and `serialize_event` in
`src/trading_bot/audit/`.
**Cheapest discriminating check:**
`uv run pytest -q tests/test_audit.py -k "canary or allowlist"`.
**Expected failing or passing observation:** before the boundary exists the
canary appears in the serialized line and the arbitrary object is stringified;
after it exists every canary case asserts absence and the object case raises
`RedactionFailure`.
