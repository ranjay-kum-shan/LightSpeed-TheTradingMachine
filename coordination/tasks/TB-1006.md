## Objective

Provide a deterministic SQLite migration mechanism, an explicit transaction
boundary that fails closed on commit errors, and atomic local-file replacement
utilities for later durable risk, intent, experiment, and operations stores.

## Contracts and Requirements

| Contract | Relevant section or invariant | Required behavior |

| [Requirements](../../docs/01-requirements.md) NFR-REP-002 | Decision and result artefacts identify code, configuration, and data | Migration identities and checksums preserve the schema lineage needed by later stores |

## Scope

### In Scope

- Ordered, checksummed SQLite migration definitions and append-only migration
  history.
- SQLite connection configuration for foreign keys, WAL journaling, full
  synchronization, a bounded busy timeout, and explicit write transactions.
- Commit, rollback, migration replay, drift, and future-schema failure behavior.
- Atomic byte and UTF-8 text replacement using a same-directory temporary file,
  file flush, `fsync`, `os.replace`, and failure cleanup.
- Offline tests using only temporary local paths and synthetic data.

### Out of Scope

- Execution-specific intent, order, fill, ledger, or reconciliation schemas;
  TB-5002 and later execution tasks own them.
- Durable sticky risk state; TB-2003 owns its schema and policy.
- Experiment registration and result semantics.
- Replacing the existing heartbeat writer outside this task's write scope.
- Backup encryption, retention, runtime-path selection, and multi-process session
  locks.
- Live trading, broker SDKs, real credentials, or owner-dependent values.

**Approved write scope:** `src/trading_bot/storage/**`,
`tests/test_storage.py`, this task record and its handoff. Changes to
